# 硬件证据指南

硬件证据的目标是让别人知道“哪一份实现，在什么设备和条件下，观察到了什么”，不是制造一段看起来顺畅的演示。

## 先固定测试身份

开始 L4/L5 测试前记录：

- 项目、源 commit、语义版本和 locale；
- AIX 文件名、UUID 与 SHA-256（若适用）；
- Rokid 眼镜型号、固件和 AIUI host build；
- 外设类别、公开型号或协议能力；
- 测试日期、持续时间、场景和协议版本。

公开记录不要包含 MAC 地址、序列号、账号、精确位置或可追踪个人的时间模式。需要区分多台设备时使用本场随机别名，例如 `rower-a`、`hrs-b`。

## 测试记录至少包含

1. 预期行为与通过条件；
2. 实际操作顺序；
3. 数据来源和新鲜度规则；
4. 通过、失败、跳过与异常；
5. 断流、隐藏/恢复、重连、退出和资源清理；
6. 本次不能支持的结论；
7. 对应照片、短日志或视频的脱敏索引（若有）。

BLE 的“扫描到”“连接成功”“服务存在”“订阅 Promise 成功”和“收到首个合法完整数据”是不同里程碑，应分别记录。IMU 的“传感器启动”“收到帧”“识别出候选周期”和“稳定指标入账”也应分开。

## 证据质量

- 保留失败与降级，不只剪辑最佳一次。
- 测试应覆盖静止、异常运动、传感器断流、应用隐藏/恢复和正常退出。
- 指标缺失时记录 unavailable；不要用零填充或从无关字段推导。
- estimated 与 measured 使用不同来源字段和显示文案。
- 真机结果只适用于记录的型号、固件、host build、包和外设组合。
- 软件、固件或测试协议变化后，结果按新身份重新验证。

## L5 现场对照

对照前先写下样本、参考设备、时间同步、误差指标和排除规则。完成后报告全部有效样本的分布、断流与失败率，并逐项解释排除。参考设备也有误差，应记录其型号、配置和导出分辨率。

跑步、骑行、划船使用各自专项指标。可以在同一天、同一宿主条件下测试以控制环境差异，但不能把三个运动的专项分相加或按总分排名。

## 隐私、权利与保管

- 优先公开结构化结果和最小片段，不公开整段原始日志。
- 移除通知、账号、位置、轨迹、设备地址/序列号、环境声音和旁人画面。
- 拍摄他人、健身房或私人场所前取得许可。
- 厂商 UI、说明书、商标和测试设备照片的公开/再使用权单独判断。
- 原始媒体与公开摘要分开保管；Apache-2.0、PolyForm 和商业许可都不自动覆盖原始证据。
- 安全漏洞、个人数据或未经授权素材通过私密流程处理，不放在公开 PR。
