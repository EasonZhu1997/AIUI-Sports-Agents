# 证据记录与声明规则

证据等级回答“这个结论在什么环境中被证明”，不是项目质量奖章。规范定义以 [`benchmark/evidence-levels.md`](../benchmark/evidence-levels.md) 为准；本文件补充记录字段和声明规则。等级越高，必须包含前一等级需要的可复现信息，但高等级不会自动证明未测试的功能。

## 等级定义

| 等级 | 名称 | 最低证据 | 可以声明 | 不能推断 |
| --- | --- | --- | --- | --- |
| L1 | 自动化本地测试 | 固定输入、命令、通过/失败结果、commit | “本地测试通过” | AIX 闭包、宿主或真机可用 |
| L2 | 包与 Reader/Preview | 可识别包、Reader/官方 Preview 检查、hash | “该包可被本地工具读取/预览” | Craft、眼镜、BLE/IMU 真机行为 |
| L3 | Craft/宿主集成环境 | 明确版本的 AIUI Craft、InkView 或等价集成环境，带操作记录 | “在所列集成环境通过” | 真实眼镜、真实外设或户外可靠性 |
| L4 | Rokid 真机 | 绑定设备型号、固件、AIUI host build、相同包身份的操作证据 | “在所列真机组合通过” | 其他型号/固件、长期精度或现场泛化 |
| L5 | 完整现场对照 | 预先定义的方案、参考设备、重复样本、误差/失败/排除规则 | “在所列条件下达到所报结果” | 医疗有效性、所有用户/环境或其他运动 |

尚未执行的设计或源码审阅不授予证据等级；应写成 `not_run` 并列为开放门。如果某项能力只到 L1，而同一项目的另一项到 L4，结果卡必须分别标记，不能把项目整体写成 L4。

## 必需身份字段

每条 L1 以上记录至少包含：

- 项目和运动类型；
- 源 commit 与语义版本；
- 测试日期、时区和协议版本；
- 实际执行的命令或操作步骤；
- 通过、失败、跳过和开放门；
- 数据来源是 measured、estimated 还是 unavailable。

L2 以上再记录包文件名、包 UUID（若适用）与 SHA-256。L3 记录工具/宿主版本。L4 记录眼镜型号、固件、AIUI host build、外设类别和测试持续时间。公开记录不保存设备地址、序列号、账号或精确位置。

L5 还必须记录：

- 参考设备及其采样/导出方式；
- 样本量、场景、持续时间与重复次数；
- 时间对齐、缺失数据和异常值规则；
- 误差指标及分布，不只给最佳值；
- 失败次数、排除样本及排除理由；
- 已知偏差和不能支持的结论。

## 声明用语

推荐使用可核对的句式：

- L1：“commit `<id>` 的解析器在列出的合成与错误样本上通过本地测试。”
- L2：“SHA-256 为 `<hash>` 的包通过所列 Reader/Preview 检查；真机未验证。”
- L4：“该包在所列 Rokid 型号、固件和 host build 上完成 20 分钟测试；其他组合未知。”
- L5：“在所列 8 次对照中，中位误差为 X，范围为 Y–Z；两次断流已计入失败率。”

禁止使用：

- “Preview 通过，所以真机兼容”；
- “订阅成功，所以已有有效数据”；
- “设备名匹配，所以协议兼容”；
- “没有字段，所以当作 0”；
- “估算接近一次，所以达到实测精度”；
- “一个运动分数更高，所以该运动 Agent 比另一运动更好”。

## 证据升级

一次 PR 可以只达到当前需要的等级，并把后续门列为开放项。升级等级时新增记录，不覆盖或改写原始失败。软件、包、固件、host build、外设协议或测试方案任一关键身份变化后，旧证据仍可保留为历史，但不能无条件沿用为当前结论。

原始日志和媒体通常留在受控本地环境；公开仓库存放脱敏摘要、最小必要片段和可复现夹具。具体操作见 [硬件证据指南](./HARDWARE_EVIDENCE_GUIDE.md)。
