# AIUI 项目提交资料预填表

这张表用于在填写 GitHub 贡献问卷、导入 Craft、上传到眼镜或进入后续 AIUI 审核流程前，把同一份项目事实整理清楚。它不是 AIUI 官方审核表，也不会自动上传任何文件。

> 先分清四个状态：GitHub 源码公开、AIX 生成、Craft/眼镜上传、平台审核或商店发布互不等价。每一步都要单独记录结果。

## 1. 项目身份

```text
项目名称：
一句话用途：
目标用户与使用场景：
运动类型：Run / Bike / Rower / Common / 其他
AIUI 形态：对话流卡片 / 沉浸式页面 / 两者都有
公开仓库 URL：
Source commit 或 tag：
许可证：
维护者公开联系方式：GitHub Issue / 其他公开渠道
```

填写原则：项目名称、描述和仓库必须互相对应；私有仓库、带 token 的 URL、个人邮箱和内部地址不要写入公开问卷。

```text

```

只写实际使用过的版本和命令。Reader、Preview、Craft 与 Rokid 真机应分别记录，不能合写成“平台已通过”。

## 3. AIX 候选身份

```text
AIX 文件名：
语义版本：
Locale：
包 UUID：
文件大小：
平台读取的 MD5：
SHA-256：
对应 source commit：
```

包身份有任何变化，都要重新计算 hash，并重新判断 Reader、Craft 和真机证据是否仍适用。当前 AIUI Studio 前端只接受 1 KB–10 MB 的 `.aix`；若目标子项目、活动或候选另有更严格门（例如 2 MB），继续按那个明确规则执行。平台上限不会覆盖子项目规则。不要在公开 Issue 中上传含凭据、私有 SDK、未授权素材或现场原始日志的包。

## 4. AIUI Studio 创建表单

```text
智能体名称：必填，最多 20 个字符
版本号：必填，A.B 或 A.B.C；每段 0–9999
类别：必填，从当前页面动态选项中选择
功能介绍：必填，最多 500 个字符
开场白：必填，最多 500 个字符
图标：必填，jpeg / jpg / png / gif
权限依赖：网络 / 摄像头 / 语音识别 / 麦克风
预览素材：JPG / JPEG / PNG / MP4，最少 3 个、最多 5 个
agent 程序包：可选，选择 .aix
```

当前单张预览图不超过 5 MB，单个视频不超过 50 MB。功能介绍应回答“谁在什么场景下解决什么问题”，不要使用“全平台”“绝对准确”“医疗级”等未被证据支持的表述。

示例：

```text
智能体名称：AIBike
版本号：0.3.80
类别：从当前可见项中选择最贴近运动场景的一项
功能介绍：在骑行过程中以低干扰方式显示来自兼容传感器的心率、踏频与功率。
开场白：开始前请确认传感器已连接；按页面提示开始，随时可以停止并退出。
证据边界：当前公开证据为 L2；Rokid 真机 BLE/IMU 与长时间稳定性仍待验证。
```

## 6. 测试与证据

```text

```

最低边界：

- L1 只代表自动化本地测试；
- L2 才包含 AIX 与 Reader/Preview；
- L3 记录 Craft/Host 集成环境；
- L4 才能声明所列 Rokid 真机组合通过；
- L5 需要完整现场对照方案、误差、失败和排除规则。

## 7. 第三方与公开素材

```text
第三方代码/SDK：名称、版本、来源、许可证、是否修改
图片/字体/音视频：作者、来源、授权范围
规范/手册/固件：是否只引用链接，是否禁止再分发
演示截图/视频：是否已经移除账号、通知、位置、旁人和设备标识
```

根目录许可证只覆盖你有权授权的作品。来源不清楚的文件先排除，再用原创占位、合成夹具或外部链接替代。

## 8. 提交前确认

- [ ] 公开仓库、commit、AIX 和测试记录对应同一候选。
- [ ] 没有 key、token、证书、签名口令、真实 MAC、序列号、轨迹或个人数据。
- [ ] Reader/Preview 没有被写成 Rokid 真机通过。
- [ ] 权限与网络行为已最小化并写明失败状态。
- [ ] 第三方代码与素材的来源和许可证已确认。
- [ ] 失败、跳过和 Open gates 已保留。
- [ ] 已由发布负责人确认本次具体上传对象和目标。

## 9. 去哪里提交

1. 要参与本开源项目：进入仓库 **Issues → New issue → 体验与贡献问卷**，把本表中适合公开的内容填入问卷。
2. 要报告 Bug 或真机证据：选择 **Bug 与真机证据**，只提交脱敏摘要。
3. 要改代码：先用 Issue 对齐范围，再 Fork、创建分支并提交 Pull Request。
4. 要在 Craft 中测试：导入项目，完成 AIUI Code/预览、Interactive Inview 和眼镜上传；按钮名称可能因账号、地区与版本不同。
5. 要进入 AIUI Studio：打开 <https://aiui.rokid.com/space>，点击 **创建**，填写“创建智能体”表单并点击 **确认**。
6. 要提审：回到项目卡，将鼠标移到三点 **更多**，点击 **提审**，填写不超过 2000 字的提审说明，再由项目负责人点击 **提交审核**。
7. 提交后只按页面实际状态记录：**草稿 / 审核中 / 审核拒绝 / 下架 / 已上架**。当前前端没有独立、稳定的“发布”按钮，不要杜撰额外步骤。

本项目 GitHub 的“体验与贡献问卷”不是 AIUI Studio 官方问卷，也不会自动创建智能体、上传 AIX 或提交审核。Craft 上传到自己的眼镜同样不等于 Studio 已提审。
