# Rower 遥测与安全边界

Rower 是 AIUI Sports Agents 首发组的一员，但当前实现是**遥测优先、控制关闭**。本边界是治理约束，不因某台机器支持控制、某个 SDK 暴露写接口或某次写入看似成功而自动放宽。

## 当前允许

- 用户明确操作后扫描并选择标准 FTMS 划船机；
- 验证 Fitness Machine Service `0x1826`；
- 读取 Fitness Machine Feature `0x2ACC`；
- 订阅 Rower Data `0x2AD1` Notify 并解析合法完整数据；
- 在 FTMS 已就绪后，由用户选择性连接标准 HRS `0x180D / 0x2A37`；
- 本地显示与聚合配速、桨频、距离、功率、心率及字段覆盖；
- 对断流、分片、隐藏恢复、双连接降级和清理做只读验证。

## 当前禁止

- 发现、订阅、写入或调用 Fitness Machine Control Point `0x2AD9`；
- 启动/停止机器、调整阻力、设置目标或训练程序；
- 使用厂商私有字符串命令、Android AAR、Unity bridge 或未审计控制代理绕过边界；
- 根据设备名、MAC/硬件地址或历史记录自动连接；
- 手写 CCCD 替代平台标准通知 API；
- 把 GATT 连接、Feature 读取或通知订阅成功当成实时数据已可用；
- 在字段缺失、过期或结构非法时继续显示旧值、零值或推导值。

## 可用性里程碑

划船机链路应区分：

```text
idle → scanning → connecting → validating → subscribed_silent → live
```

只有首个通过 flags、长度、字段顺序、有限值和必需字段校验的完整最终数据集才能进入 `live`。分片未完成、通知静默或数据过期时，应保持等待/不可用并清除相应指标，不补算断流期间的数据。

HRS 是可选链路。它失败、接触不良或过期时不能阻断 FTMS 划船训练；如有新鲜合法的 FTMS 心率可以明确回退，否则心率为 unavailable。两台外设能否在目标 AIUI 宿主同时维持连接必须由 L4 证据证明。

## 网络与数据

划船训练的核心遥测和本地总结默认可离线运行。任何聚合上传必须单独显式启用，列明字段、接收方、重试、保留与删除方式。不得默认上传设备名、设备标识、原始 BLE 包或逐包数据。

## 未来控制提案

未来若确有控制场景，必须作为高影响决策单独提出，至少包含：

- 明确用户价值、非控制替代方案和现实危害分析；
- 独立协议契约、兼容矩阵、权限与状态机；
- 每次操作的可见确认、超时、撤销、停止和物理优先级；
- 写响应与实际机器状态的双重确认，禁止只凭 transport ACK 宣称成功；
- 恶意包、断连、重放、迟到响应和错误目标设备测试；
- 私密安全评审、L4 真机故障测试和分阶段发布计划。

在上述提案获得治理批准并另行发布前，任何含控制路径的 PR 都应被拒绝或移出首发范围。
